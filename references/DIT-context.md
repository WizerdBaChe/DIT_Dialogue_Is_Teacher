# DIT — Domain Glossary
<!-- One definition per term. Updated live, never batched. English only. -->

- **Primary View** (2026-07-19): The mutually exclusive central content state, limited to Overview, Reader, or Subagents.
- **Overview** (2026-07-19): The reusable session-orientation surface that explains the current session and provides the first actionable learning steps.
- **Session Origin** (2026-07-19): The provenance flag indicating whether the current document came from the built-in sample or user input; it affects orientation copy only.
- **Structure Sidebar** (2026-07-19): The persistent desktop or drawer-based narrow-screen textual navigator for the current session.
- **Current Position** (2026-07-19): The selected or playing ViewItem index and total count; it does not represent learning completion.
- **Minimap** (2026-07-19): The bounded Reader overlay that previews the session shape and current position and opens the Session Map.
- **Session Map** (2026-07-19): The modal fishbone-based global navigation surface with semantic zoom, preview selection, and explicit jumps to Reader items.
- **Map Landmark** (2026-07-19): A map target backed by exactly one real ViewItem id and therefore eligible for Reader navigation.
- **Map Cluster** (2026-07-19): A deterministic visual aggregation of consecutive real items that can refocus or zoom the map but cannot directly navigate to Reader.
- **Semantic Zoom** (2026-07-19): A map-level transition that changes the categories and aggregation of visible information instead of merely scaling identical graphics.
- **Endpoint Provider** (2026-07-24): The single pluggable teaching-layer provider that replaces the old `ollama`/`cloud` split and talks to any OpenAI-compatible (or Anthropic-messages) endpoint, driven entirely by the selected Preset's metadata.
- **Preset** (2026-07-24): A named endpoint configuration plus metadata (kind, transport, needsKey, sendsDataOut, cost, browserReach, modelsProbe) that fully determines the provider panel's UI affordances.
- **Local Proxy** (2026-07-24): A localhost server (opencode / LiteLLM) that relays DIT's calls to a cloud provider the browser cannot reach directly because of CORS; the API key stays in the proxy, not the browser.
- **BYOK** (2026-07-24): Bring Your Own Key — the user supplies their own API key to reach a browser-directable cloud (Anthropic) or to configure a Local Proxy.
- **Config File** (2026-07-24): `dit.config.json`, an app-sibling file fetched at runtime to persist BYOK keys across sessions; it is git-ignored, excluded from `dist/` and exports, and never rendered into the UI.
- **Source Profile** (2026-08-14): a `SourceId`-keyed table (`core/source/profiles.ts`) of edit/investigation/ambiguous tool sets and file-path key shapes, resolved once at normalize time so `denoise()`/`distill()` classify spans per-harness instead of matching hardcoded Claude Code tool names against every source.
- **Outcome-unknown** (2026-08-14): `ResultInfo.outcomeUnknown` — true when the source recorded no success/failure signal for a tool call at all (e.g. Codex plain `exec`), distinct from `isError: false` (source said it succeeded). Exists so "not recorded" is never silently coerced into "succeeded".
- **r11-release-readiness** (2026-08-15): round id for the fix-up pass whose exit condition is D-004's merge gate — the three 2026-08-03 release blockers plus the seven defects the 2026-08-15 manual UAT surfaced. Deliberately not a feature round.
- **r11.1-text-rendering** (2026-08-15): round id reserved for the Markdown/LaTeX render layer split out of R11. Design guidance already exists at `docs/design/DIT_TEXT_RENDERING.md`; no code written.
- **Skeleton coverage** (2026-08-15): the share of a session's spans that become spine nodes rather than ribs. A session whose spine is only {start, end} has near-zero coverage and reads as a flat list of side branches — the R11-M5 symptom on Codex sources. Distinct from *parity*, which compares two sources' outputs and can pass while both are impoverished.
- **r11.2-uat-repairs** (2026-08-16): round id for the repair pass on the defects R11's manual acceptance surfaced (8 pass / 4 partial / 5 fail / 7 untestable). Branch `feat/r11.2-uat-repairs`, cut from `feat/r11-release-readiness`. Its exit condition is the R11 acceptance card passing, which reopens D-004's merge gate. Not the render layer — `r11.1-text-rendering` stays reserved.
- **Disclosure** (2026-08-16): the D-006 mechanism — when a detector finds something it is not going to redact, the export says so with a count (「另偵測到 N 筆疑似高熵字串（未遮）」) rather than staying silent. Distinct from *redaction*, which removes the value. The count is by **containment**, not overlap: a string half-covered by another rule still has characters in the output, so it still counts. Reporting a redaction that did not happen is the failure this exists to prevent.
- **r10.1-codex-session-provenance** (2026-08-15): round id for the RCA into Codex exec-name resolution and `*_end` event pairing failures, opened after manual UAT on r10-source-awareness surfaced duplicate-looking cards and leaked wrapper tags. Root cause and a P0-P3 remediation plan exist; implementation not started as of Phase 13.
- **Source Profile** (2026-08-26): the per-`SourceId` table that describes a harness to the rest of the codebase, so nothing outside it needs an `if (source === …)`. Introduced at R10-B covering the RENDER side (denoise/distill tool-name shapes); R12 adds a DISCOVERY half. INV-R12-1: a source branch outside the profile is a defect, not a style choice.
- **Discovery Half** (2026-08-26): the R12 addition to Source Profile — `rootHint`, `transcripts`, `sidecars`, `titleLadder`, `classify`. Held as a typed exhaustive `Record<SourceId, …>` so adding a source fails `tsc` until its row exists. That compile failure IS the mechanism; a registry that cannot fail that way has not made the rule structural.
- **Sidecar** (2026-08-26): session metadata that lives OUTSIDE the transcript file and must be joined back by id. Codex's session purpose is the case that named it: `.codex-global-state.json` → `electron-persisted-atom-state` → `thread-descriptions-v1`, keyed by `session_meta.payload.id`. Contrast Claude Code, whose titles are records inside the transcript. This is why the Codex root is `~/.codex` and not `~/.codex/sessions` — a browser cannot read the parent of a picked directory.
- **Source-First Navigation** (2026-08-26): the R12 navigation shape — level 1 picks the agent system (Claude Code or Codex, the only two supported), level 2 offers the existing collection/single-file modes. Discovery branches per source; viewing converges on one unchanged `SessionDocument` and one viewer.
- **Title Ladder** (2026-08-26): the ordered rungs a source declares for deriving a session title, replacing the single hard-coded ladder in `pickTitle` whose top two rungs (`custom-title`, `ai-title`) exist only for Claude Code. Claude: custom → ai → derived → filename. Codex: sidecar → derived → filename. Every rung below the first is a NAMED degradation with its own `titleSource` and its own affordance, never a silent fallback.
- **r12-source-first-navigation** (2026-08-26): round id for the discovery/viewing split. Note for anyone reading older records: Phase 16 deferred an unrelated set of items "to R12" before this id was allocated to this theme. Those items are now `docs/DEFERRED.md` DW-01..DW-17, all `home: unassigned` — **none of them is in R12's scope**.
- **Round ID Allocation Registry** (2026-08-26): `docs/rounds/ROUNDS.md`, the single source of truth for which round ids exist. It exists because the directory listing never was one — R4 shipped before the convention and has no directory, R11.1 is reserved without one — so a writer checking `docs/rounds/` sees a free id that is not free. Allocation is checked by `npm run check:rounds`.
- **Deferred Work Register** (2026-08-26): `docs/DEFERRED.md`, holding decided-but-unhomed work as `DW-NN` items whose `home` is either an allocated round id or the literal `unassigned`. It replaces the phrase "deferred to R<next number>", which reserves an id for a theme that has not been chosen yet — the mechanism behind both the R9 and the R12 collision.
- **Live record vs frozen round document** (2026-08-26): a live record (`references/DIT-*.md`, `docs/DEFERRED.md`, `CLAUDE.md`) describes the present and is corrected in place; a frozen round document (`docs/rounds/**`) is evidence of what was true when written and is corrected by a dated note appended to it, never by rewriting the verdict. `check:rounds` scans only the former, by design.
- **Attribution** (2026-08-26): which named skill, subagent or MCP tool produced a step, held on the span as a source-agnostic `Attribution[]` (`kind` + verbatim `name`, plus `server` for MCP). An array because they co-occur — 646 records carry skill+agent. Absent means "the source did not label this step"; `SourceProfile.attribution.kinds` being empty means "this source never labels steps". Those are different facts and the viewer must not render them the same way.
- **Named degradation vs the fallback channel** (2026-08-26, sharpened): a degradation the user can SEE — its own `titleSource`, its own badge, its own diagnostic — travels as a `Diagnostic`; only a substitution the user cannot observe goes through `reportFallback`. R12 M7 found the reverse error too: a silent `?? "claude-code"` in `finalizeMeta` that should have been on the fallback channel and was on neither.
- **Round ID Allocation Registry / numeric namespace closed** (2026-08-26): `docs/rounds/ROUNDS.md`. R1–R12 are a closed legacy namespace; new rounds use `<YYYY-MM>-<slug>`, which cannot be forward-referenced because writing the id requires naming the theme, and naming the theme is allocating the round. Enforced by `npm run check:rounds`.
- **Live record vs frozen round document** (2026-08-26): a live record (`references/DIT-*.md`, `docs/DEFERRED.md`, `docs/rounds/ROUNDS.md`, `AGENTS.md`, `CLAUDE.md`) describes the present and is corrected in place; `docs/rounds/**` is evidence of what was true when written and, since 2026-08-26, is closed even to annotation — a misleading frozen document is fixed in the register, not in the document.
- **Exhaustively guarded dispatch** (2026-08-27): the sanctioned exception to INV-R12-1. A per-source `if`/`switch` is acceptable where a `const _: never = source` assertion makes a new `SourceId` fail to compile — the invariant's purpose is that a new source can never silently do the wrong thing, not that a particular syntax is banned. An exhaustive `Record<SourceId, …>` protects data tables; it does not protect branch dispatch, which is why both are needed.
- **Type assertion vs annotation** (2026-08-26): `{...} as Record<SourceId, T>` does NOT require every key — only an annotation (or `satisfies`) does. Verified by deleting a key and passing `tsc --noEmit`. Any per-source table written with `as` is a declaration nothing holds to the truth; see P-004.
