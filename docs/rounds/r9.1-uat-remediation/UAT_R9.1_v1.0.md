## A. 三個正確性缺陷

### A1 — 資料夾第一次就要成功（額外回報 #0）▸ RC-A

1. DevTools → Application → Storage → **Clear site data**，重新整理。
2. 關掉歡迎彈窗。
3. 點「**挑選 Session**」（現在是左邊那顆主按鈕），選 `C:\Users\gunda\.claude\projects\C--Users-gunda--claude`，按「開啟」。

**預期**：**第一次就列出清單**。若仍失敗，畫面上必須出現「資料夾讀取失敗」＋重試鈕——
**絕不可以什麼都沒發生**。即使失敗，這一項也算得到有用結果：請把錯誤訊息裡的括號內容抄給我。

**我已驗證**：機制已定位——`pickAndIndexDirectory` 原本把「挑選」與「索引」包在同一個 `try` 裡，
而取消的判準是 `AbortError`；剛授權的 handle 上 `getFile()` 正好會丟 `AbortError`，於是索引失敗
被讀成「使用者按了取消」，落到唯一會讓瀏覽器整個消失的狀態。已拆成兩段，並補了三條轉移測試
（索引失敗 → `index_failed`；索引階段的 `AbortError` → `index_failed`；真正的取消 → `closed`）。
**為什麼還需要你**：`showDirectoryPicker()` 需要真人手勢，自動化無法觸發那條真實路徑。

### A2 — 只選 `subagents/` 底下的檔案（**R9 唯一未通過項**）▸ RC-C

1. 用「載入單一檔案」的多選，只選 `…\66c03ab2-…\subagents\` 底下的兩個 `.jsonl`。

**預期**：跳出具名錯誤——「這個資料夾裡只有子代理紀錄，主檔是它的同層兄弟檔……」，
按確認可關閉，**上一份 session 沒有被清掉**。**不應該**再出現「只有兩個子代理節點、

**我已驗證**：根因是子代理身分只看路徑字串，而一般多檔選取的 `webkitRelativePath` 是空字串，

（全部 `isSidechain`，或帶 `agentId`），並補了兩條 pipeline 測試（裸檔名的子代理必丟
`NO_MAIN_TRANSCRIPT`；主檔＋裸檔名子代理仍正確挑到主檔）。

### B2 — 三顆按鈕一樣大（#4）▸ RC-E

**預期**：總覽頁那一排「開始閱讀／挑選 Session／載入單一檔案」三顆**等高**。

**我已驗證**：在真瀏覽器量過——修改前 40 / 30 / 30（`<label>` 與 `<button>` 的落差是意外，

**設計說明（回答你的問題）**：原本**沒有**共用的按鈕抽象層，`.btn` 只是一組外觀宣告，

尺寸走 `--btn-min-h` 變數而不是各處自己寫 padding。全專案 43 個使用點掃過一遍，
per-site 的尺寸覆寫收回 token 層。依你的裁決**沒有**新建 `<Button>` 元件——先消除不一致，
是否值得抽象留待日後。

## F. B5 的處置：從「未驗」改記為「無法驗」

作者裁決：**Firefox / Safari 在本環境跑不了，沒有測試依據。**

這不是把它降級，是把帳記對。「還沒驗」暗示它遲早會被驗掉，於是每一輪的清單都留著它、每一輪都
沒動——那條目的存在只是在製造「有在追蹤」的錯覺。實際狀況是：**沒有可用的驗證管道**。

因此改為：

- `webkitdirectory` 後備路徑的保證等級明確降到**只有型別與單元層**，不宣稱瀏覽器層可用。
  任何文件都不得寫「Firefox/Safari 可用」，只能寫「有後備實作，未在該環境驗證過」。
- 這是**已知未知**，不是待辦。移出 UAT 清單，登在 `docs/BACKLOG.md` 的「無法驗證項」。
- 解除條件（任一成立才重新變成待辦）：拿得到 Firefox/Safari 的實機或雲端測試環境；
  或建立 `tests/e2e/` 並接上跨瀏覽器執行器（該缺口 R9 已登 BACKLOG）。
- 風險敘述：若後備路徑其實是壞的，非 Chromium 使用者會在點「挑選 Session」時拿到一個
  不會列出任何東西的檔案選擇器。**這個風險目前沒有偵測手段**——沒有人會回報，因為沒有人在用。
