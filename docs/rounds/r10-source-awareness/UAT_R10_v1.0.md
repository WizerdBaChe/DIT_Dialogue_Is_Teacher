## A　M1｜Codex 子代理訊息不再被吞掉

前置：準備一份**有子代理**的 Codex rollout。判斷方法：該 session 期間你有讓 Codex 派子代理
（例如 review／explore 類的任務）。本機 356 份裡有 59 份帶 `thread_spawn`，200 份的
`thread_source` 是 `subagent`。

| # | 動作 | 預期觀察 |
|---|---|---|
| A1 | 載入該 rollout，**先不要開啟子代理旁鏈** | 畫面與修改前**完全一樣**。這是刻意的：預設值沒有變 |
| A2 | 開啟子代理旁鏈（Reader 的旁鏈開關） | 出現先前不存在的訊息卡。內容應是子代理任務的指派與回報，不是空白卡、不是「未知事件」 |
| A3 | 找一則「主代理 → 子代理」的訊息 | 應呈現為**提問／指示**那一側（user 樣式），因為它就是交給子代理的提示 |
| A4 | 找一則「子代理 → 主代理」的訊息 | 應呈現為**回覆**那一側（assistant 樣式） |
| A5 | 檢查有沒有亂碼或超長 base64 區塊 | **不應該有**。`encrypted_content` 已排除；若看到亂碼即為缺陷 |
| A6 | 開 DevTools Console | 無錯誤。診斷訊息裡 `CODEX_COORDINATION_SKIPPED` 的計數應**明顯下降**（先前把這些訊息也算進去了） |

### 壓力路徑

| # | 動作 | 預期觀察 |
|---|---|---|
| A7 | 反覆快速開關子代理旁鏈 10 次以上 | 不閃爍殘影、不重複插入、計數不累加、不當掉 |
| A8 | 載入一份**沒有**子代理的 Codex session | 完全沒有新增卡片；行為與修改前一致 |
| A9 | 載入一份 **Claude Code** session | 完全不受影響（這次只動 Codex adapter） |
| A10 | 用最大的一份 rollout（本機最大 3,202 行）重跑 A2 | 開啟旁鏈後仍可捲動，無明顯卡頓；載入不失敗 |
| A11 | 對 A2 的 session 做一次**逐字稿匯出**（Markdown） | 子代理訊息依現行規則預設排除，且輸出應誠實報出被排除的節點數，不是靜默丟掉 |
| A12 | 對同一 session 做一次**快照匯出**並開啟該 HTML | 快照內的呈現與 Reader 一致（兩條渲染路徑不得分岔） |

### 若 A2 沒有出現任何新卡片

不要當成通過。可能是：(a) 這份 session 其實沒有子代理訊息——換一份再試；(b) 旁鏈開關沒有作用到
Codex 來源。請回報你用的 session 大概有幾個子代理任務，這是往下追的唯一線索。
