# DIT 文字渲染設計引導（Markdown / LaTeX）

> 狀態：**設計引導，尚未施工**。作者 2026-07-29 裁決 F3——R9.1 不實作，但要先把上下文寫下來，
> 避免下一輪在沒有依據的情況下憑空推測。
> 觸發：R9 UAT 額外回報 #7「目前的畫面內沒有渲染 md 格式的文字（也缺少 LaTeX 支援）」。
> 現況（2026-07-29 實測）：`package.json` 無 `marked` / `remark` / `markdown-it` / `katex` 任何一項；
> `src/` 內 0 處 `dangerouslySetInnerHTML`。所有訊息文字都是純文字節點。

---

## 1 這是缺功能，不是缺陷

Transcript 裡的文字本來就是 Markdown——AI 的回覆幾乎必然帶反引號、清單、粗體、程式碼區塊，
研究類對話還會帶 `$...$`。DIT 目前把它們原樣顯示，所以使用者看到的是 `` `foo` `` 而不是 `foo`。
沒有任何東西壞掉，只是這一層從來沒有做過。

因此本文件不是修正案，是**下一輪的邊界條件**。

---

## 2 三個必須先想清楚的約束（這是本文件存在的理由）

### 2.1 這是不可信輸入，不是作者自己寫的內容

要渲染的文字來自 AI agent 的執行紀錄——內容可能包含使用者貼進去的網頁片段、工具輸出、
攻擊者可控的檔案內容。**渲染 = 把不可信字串變成 DOM**，這是這個功能的主要風險面。

立場（建議，未定案）：
- **不得**出現 `dangerouslySetInnerHTML` 而不經淨化。目前全專案 0 處，這個乾淨狀態值得守住。
- 首選是**不產生 HTML 字串**的路線：解析成 token/AST，再由 React 建元素。沒有 HTML 字串，
  就沒有注入面，也不需要引入淨化器當作補救。
- 原始 HTML（Markdown 允許內嵌 HTML）一律**當純文字顯示**，不解析。DIT 是閱讀器，不是預覽器。
- 連結：預設不可點，或只顯示 URL 文字。可點連結會把「讀紀錄」變成「可被紀錄內容導流」。

### 2.2 有兩條渲染路徑，不能只做一條

| 路徑 | 位置 | 限制 |
|---|---|---|
| 閱讀畫面 | `src/components/SpanCard.tsx`、`GroupCard.tsx`、`parts.tsx` | 走 React；有虛擬捲動（`@tanstack/react-virtual`），渲染成本會被乘以可見卡片數 |
| 匯出快照 | `src/core/export/snapshotTemplate.ts` → `dist/snapshot.html` | **單檔**產物，`vite-plugin-singlefile` 把所有東西內聯 |

兩條路徑對同一段文字必須產出**同樣的樣子**。做了閱讀畫面卻沒做快照，等於匯出後的檔案跟畫面
不一致——那比兩邊都不渲染更糟。**這一條是選型的主要約束，不是附註。**

### 2.3 單檔快照的體積

目前 `dist/snapshot.html` 約 435 KB（gzip 136 KB）。KaTeX 的字型與 CSS 若整包內聯，會是同一個
量級的增量。**LaTeX 與 Markdown 應該分兩次做、分開評估**，不要綁在同一個決策裡。

## 3 範圍邊界（建議，待下一輪裁決）

**第一階段（低風險、覆蓋絕大多數實際內容）**
- 行內程式碼（單反引號）
- 圍欄程式碼區塊（三反引號，含語言標記；**不做語法高亮**，那是另一個體積決策）
- 粗體、斜體
- 清單（有序／無序，單層）

**第二階段**
- 標題、引言區塊、表格、分隔線
- 連結（依 2.1 決定可點與否）

**第三階段（獨立評估）**
- LaTeX（`$...$` / `$$...$$`）

**明確不做**
- 內嵌 HTML、圖片載入（外部請求）、Mermaid 之類的圖表語言、語法高亮（除非體積另有裁決）。

---

## 4 選型判準（不預先指定套件）

任何候選都要同時回答這五題，答不完整就不要選：

1. 能不能**不產出 HTML 字串**？（→ 2.1）
2. 打包後大小多少？內聯進單檔快照後 `dist/snapshot.html` 增加多少？（→ 2.3）
3. 同一個實作能否同時供閱讀畫面與快照使用？（→ 2.2）
4. 在虛擬捲動下每張卡片的解析成本可否被快取（例如按 span id memo）？
5. 不支援的語法會不會靜默吃掉內容？**寧可原樣顯示，不可悄悄消失**——這是本專案既有的偏誤方向。

> 版本與體積是易變外部事實，選型當下必須實查，不得沿用本文件的印象。

---

## 5 與既有不變式的關係

- **降級要看得見**：解析失敗的段落應原樣顯示原始文字，並在該卡片留下可見痕跡，而不是空白。
- **沒有靜默 fallback**：若走了「無法解析就當純文字」的路，那是一條具名降級（見 R9.1 RC-B
  對兩種降級的區分），走診斷通道而非 `reportFallback`。
- **卡片是可虛擬化的**：任何渲染實作都不能讓卡片高度在解析完成後才確定，否則捲動位置會跳。

## 6 未決問題（留給下一輪的作者裁決）

1. 連結要不要可點？（安全 vs 便利，這是價值取捨，不由實作層決定）
2. 程式碼區塊要不要語法高亮？（體積 vs 可讀性）
3. LaTeX 是否值得為它讓出約 100 KB 以上的單檔體積？取決於作者實際會讀的 session 類型。
4. 講解層（annotation）產出的文字是否適用同一套渲染？來源不同（本地／雲端模型），信任等級也不同。
